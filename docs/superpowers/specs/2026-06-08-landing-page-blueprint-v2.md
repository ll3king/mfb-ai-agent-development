# Landing Page Blueprint V2

## Goal

Replace the current landing page direction with a clearer, harder, more buyer-specific sales page for the `done-for-you AI Chief of Staff implementation` offer.

This blueprint exists because the current page is directionally better than the earlier versions, but still fails the real requirement:

- it does not convert clearly enough
- it still abstracts the offer too much
- it still says operational control more than it shows it

## Audit verdict

The current page should not be treated as final.

It is stronger than a generic AI agency page, but it still misses on the main job:

1. the primary CTA is not a real live conversion path
2. the offer remains too abstract and not concrete enough
3. the page still leans too early on `AI Chief of Staff` language instead of fully driving the founder bottleneck first
4. buyer self-recognition is still too broad
5. the visual language still does not fully translate the business mechanism into a distinctive symbol system

## Strategic correction

The page is not selling an AI concept.

It is selling an intervention:

`remove the founder from the role of operational routing layer`

That means the page should no longer be built around a general dark premium service aesthetic first.

It should be built around one core symbolic story:

`most work still hits the founder today; after installation, only exceptions reach the founder`

## Chosen symbolic system

### Name

`Bottleneck Command Layer`

### Core story

The founder is currently the choke point.

The installed system reroutes normal work away from the founder and sends only high-impact or ambiguous exceptions upward.

### Core symbols

- `Source nodes`
  Small muted entry points for requests, inbox items, follow-up obligations, and approvals.

- `Routing lanes`
  Clean system paths for normal work that should not require founder intervention.

- `Escalation gate`
  A single highlighted gate where only exception cases rise upward.

- `Founder anchor`
  A single stable founder position that acts as judgment desk, not general traffic handler.

- `Status beacons`
  Sparse indicators of movement, ownership, and exceptions without turning the page into a SaaS dashboard.

### Emotional contrast

- `Pain state`
  Congestion, collision, compression, too many flows converging on one point.

- `Control state`
  Ordered lanes, clear separation, one exception path, founder sees only what deserves judgment.

## Hero direction

### Recommended concept

`The Last Bottleneck`

### Why this concept wins

It is the strongest single-frame expression of the offer:

- one person still carrying too much operational traffic
- one visible exception gate
- one clear sense that most work should no longer terminate there

It is better than a generic founder-under-pressure poster because it gives the buyer a mechanism, not just a mood.

### Hero structure

1. `Headline`
   Not an AI phrase.
   It must state the founder bottleneck directly.

2. `One short support line`
   Explain that the intervention installs a system that routes normal work away from the founder.

3. `One primary CTA`
   `Book Your Bottleneck Audit`

4. `One high-trust proof line`
   One sentence only.
   No supporting card cluster.

5. `One decisive image / symbol system`
   The image must visibly show:
   - inbound work
   - founder choke point
   - rerouted normal flow
   - exception-only elevation

### Hero composition contract

Use this as the concrete implementation contract for the next page:

- `brand line`
  Minimal brand plus one-line service descriptor.
  No trust wall.

- `hero grid`
  Two primary columns only:
  - `hero-copy`
  - `hero-visual-command`

- `hero-copy` contains exactly:
  - overline: `The Last Bottleneck`
  - one H1 with founder bottleneck statement
  - one support line explaining what gets rerouted away from founder
  - one primary CTA: `Book Your Bottleneck Audit`
  - one proof sentence
  - three compact inline proof tokens only:
    - `routing`
    - `follow-up`
    - `exceptions`

- `hero-visual-command` contains:
  - one decisive image
  - source nodes
  - routing lanes
  - one escalation gate
  - one founder anchor

No dashboard counters.
No feature tiles.
No copy-heavy overlay stack.

### Hero must avoid

- long explanatory copy
- dashboard-like floating feature cards
- multiple competing proof modules
- decorative trust strips
- a hero that can only be understood after reading the copy

## Replacement information architecture

The next page should use at most 6 sections.

### 1. Hero

Purpose:
- stop attention
- make the founder bottleneck immediate
- establish the intervention in one glance

Must prove:
- this page is about founder-led agency operational drag
- this is not a generic AI offer

### 2. Qualification section

Working title:
`If this sounds familiar`

Purpose:
- let the buyer self-identify in under 10 seconds

Must prove:
- the visitor is in-scope
- the problem is their current operating reality

Format:
- short checklist or short operational markers
- not a long paragraph

### 3. Consequence section

Working title:
`What founder-routing actually costs`

Purpose:
- make the pain feel business-relevant

Must prove:
- this is not just inconvenient
- it damages execution speed, follow-through, and decision quality

Format:
- strong operational consequences
- not generic productivity language

### 4. Mechanism section

Working title:
`What we actually install`

Purpose:
- make the offer concrete

Must prove:
- this is a bounded operating intervention
- this is not software resale
- this is not prompt engineering theater

Allowed structure:
- Intake
- Routing rules
- Follow-up engine
- Escalation visibility

Each block must describe the operational output, not a feature category.

### 5. Execution contract section

Working title:
`How the implementation works`

Purpose:
- reduce fear of vague AI projects

Must prove:
- the project is scoped
- the path is bounded
- there is a real handoff and implementation contract

Recommended flow:
1. Audit
2. Workflow map
3. Install and handoff

Also state:
- what is included
- what is not included

### 6. Decision and CTA section

Purpose:
- close the page cleanly

Must prove:
- who this is for
- why the audit is worth taking now
- what the next step produces

Must end with:
- one CTA only
- no generic “contact us” feeling

## Concrete section copy

This is the approved content direction for the next rebuild.

### 1. Hero

**Headline**  
`The Last Bottleneck in Your Agency`

**Support line**  
`Your agency can scale in systems, not in your attention. We install routing so follow-up, approvals, and handoffs stop coming to you unless they truly need founder judgment.`

**Proof line**  
`Done-for-you Bottleneck Command Layer for Australian founder-led agencies.`

**Primary CTA**  
`Book Your Bottleneck Audit`

### 2. Qualification

**Section title**  
`If this sounds familiar`

**Intro line**  
`Most founder-led agencies still run execution as if the founder is the operating system.`

**Checklist markers**
- requests, follow-ups, and approvals still pass through you before moving forward
- team members wait on founder clearance for non-strategic decisions
- execution depends on your memory and inbox timing
- context is lost in scattered chats and not carried by process
- work slows when your availability determines progress
- you want founder-time for judgment, not operational traffic management

### 3. Consequence

**Section title**  
`What founder-routing actually costs`

**Core line**  
`When routing stays in founder bandwidth, speed, execution quality, and client trust weaken together.`

**Pressure line**  
`You are not short of strategy, you are paying strategic tax on operational drag.`

**Outcome markers**
- every manual handoff compounds delay
- follow-up gaps become recoveries, not growth
- escalation decisions arrive late, then escalate higher in cost and stress

### 4. Mechanism

**Section title**  
`What we actually install`

**Core framing**  
`Not a new app. A bounded founder-routing architecture.`

**Four blocks**
- `Source nodes`: structured intake for requests, follow-ups, approvals, and handoffs
- `Routing lanes`: rules that move routine work to teams without founder intervention
- `Escalation gate`: only exception cases rise to you, with clear reasons and context
- `Status beacons`: concise visibility of progress, ownership, and pending decisions

### 5. Execution contract

**Section title**  
`How the implementation works`

**Flow**  
`1) Bottleneck Audit -> 2) Workflow Map -> 3) Install + Handoff`

**Included**
- Bottleneck Audit, one scoped 60-minute working session
- workflow map across intake, routing, follow-up, and escalation
- installation of a bounded routing system
- founder and team handoff with decision rules and ownership boundaries

**Not included**
- open-ended AI consulting
- ongoing day-to-day operations management
- unlimited tool or agent build-outs outside the scoped workflow surface

**Outcome line**  
`A clear implementation path plus founder-only escalation logic, so your operation runs without routing all work through you.`

### 6. Decision and CTA

**Section title**  
`The last step to reclaim founder attention`

**Decision line**  
`Built for founder-led Australian agencies where the founder is still the routing layer.`

**Continuation line**  
`If this sounds like your current state, one call clarifies if we can remove founder drag in one bounded implementation.`

**Close line**  
`If the fit is real, the next step is immediate and specific: a real operational handoff.`

**Primary CTA**  
`Book Your Bottleneck Audit`

## Copy direction

### The page should say less often

- AI Chief of Staff layer
- operating layer
- working layer
- implementation path

These are strategically correct but too abstract when overused.

### The page should say more often

- founder is still the operating system
- too much work still routes through you
- only exceptions should reach you
- approvals should not queue in private messages
- follow-up should not depend on founder memory
- execution should not collapse into founder bandwidth

### Voice rules

- concrete
- pressure-aware
- not theatrical
- not startup-hype
- not AI-solutionist

## Visual rules for the next redesign

### Keep

- dark premium atmosphere
- one warm accent
- sans-led typography
- light asset footprint

### Remove

- generic AI-startup cues
- feature-card storytelling as the main page grammar
- repeated section labels unless they carry meaning
- fake trust devices
- visual dependence on text alone to explain the mechanism

### Stop doing in the current page

- remove top navigation links that split attention before the page has sold the problem
- remove the secondary hero CTA
- remove dashboard-like overlay stacks such as signal cards and vertical signal strips
- remove copy clusters that restate the same mechanism in softer language
- remove placeholder footer notes from final output
- remove any non-live primary CTA path

### Upgrade

- image as mechanism, not decoration
- stronger contrast between congestion and exception-only routing
- fewer but sharper interface cues
- more positional meaning in the layout itself

## Implementation constraints for the next design round

- one real primary CTA path should exist before treating the page as final
- one dominant symbolic system should govern the whole page
- no section should restate the previous section in softer words
- if a visual element does not help explain the bottleneck or the rerouting model, remove it

## Lightweight visual devices

To express the `Bottleneck Command Layer` without drifting into a SaaS dashboard:

- use one layered flow motif: inbound nodes -> routing lanes -> escalation gate -> founder anchor
- use one subtle exception pulse only near the escalation gate
- use simple lane state labels such as `normal flow`, `pending`, `exception`, not numeric metrics
- keep routine paths muted and reserve the warm accent only for the exception channel
- keep overlays sparse: 2 to 3 short labels maximum
- any motion must respect `prefers-reduced-motion`

## Recommended next action

Do not polish the current page incrementally.

Use this blueprint to produce a true `landing page vNext-2` redesign from scratch, starting with:

1. a new hero composition based on `The Last Bottleneck`
2. a 6-section page rebuild
3. a real CTA path

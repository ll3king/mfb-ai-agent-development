# Chief of Staff Landing Page Design

## Goal

Design the final landing page for the `AI Agent Development` child project using `Chief of Staff` pain as the market-facing packaging, while actually selling a `done-for-you implementation project` for founder-led agencies.

## Approved positioning

- market: Australia first
- buyer: founder-led agencies
- packaging: `AI Chief of Staff`
- actual offer: personalised done-for-you implementation
- primary sale: one-off implementation project
- secondary sale: optional monthly managed optimisation / maintenance

## Core problem statement

The founder becomes the operational bottleneck because too much coordination, follow-up, task routing, and information handling still flows through one person.

This page is not about showing off AI capability.
It is about making that bottleneck feel specific, costly, and solvable.

## Page strategy

### Primary framing

`Founder bottleneck`

### Secondary framing

- do not hire ops too early if the operating logic is still undefined
- protect execution and revenue by reducing founder dependency

## What the page must communicate

1. The buyer has a real operating pain, not a vague curiosity about AI.
2. `Chief of Staff` is the right mental model for the pain.
3. The service is done-for-you design and implementation, not software access.
4. Personalisation is part of the value.
5. The buyer can engage through a scoped implementation conversation.

## What the page must avoid

- generic AI agency language
- broad SaaS framing
- overpromising autonomy
- positioning that sounds like a chatbot or off-the-shelf assistant
- turning the page into a sales follow-up-only offer

## Recommended page structure

1. Hero
2. Founder bottleneck pain section
3. Reframe from "more tools" to "AI Chief of Staff system"
4. Implementation scope
5. Why done-for-you / why personalisation matters
6. Offer structure: project first, maintenance second
7. Outcome section
8. CTA section

## CTA design

Primary CTA:

`Apply for a Chief of Staff Implementation`

The CTA should lead to a scoped implementation conversation, not a generic waitlist.

## Success criteria

The final page should make a founder-led agency owner think:

- this is describing my current bottleneck accurately
- this is more concrete than generic AI automation
- this is something I would pay someone to implement properly

## Scope note

This design is only for the landing page and immediate sales logic.

It does not define:

- product architecture
- internal software stack
- long-term platform roadmap
